This diagram reflects the actual code paths in webapp/app.py and webapp/static/app.js. "No connection to the internet" isn't just a claim here — it was verified empirically by monitoring live network connections during a real request (see TESTING_PLAN.md §2), and Ollama's own cloud/remote-inference feature is explicitly disabled (OLLAMA_NO_CLOUD=1, see PRODUCT_DEFINITION.md §7).
OCR only runs when a page actually needs it. Most PDFs from an EHR export already have a real, embedded text layer, so pulling the text out is fast and exact — OCR is unnecessary overhead there and would only introduce more error. The app detects which pages are which automatically: it extracts text from every page first, and only if that page yields under ~20 characters (a reliable signal for "this page has no real text layer," i.e. it's a scanned image or a fax) does it fall back to OCR for that specific page. Everything else is read directly, no OCR involved. Pages that did need OCR are called out explicitly in the results as a warning, since OCR text is less reliable than a native text layer — and the document viewer can't auto-highlight passages on those pages (there's no text layer in the original PDF itself for it to search), so it says so rather than guessing.
